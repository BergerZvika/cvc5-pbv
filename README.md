# Artifact: Parametric Bit-Vectors in cvc5 — evaluation

This directory reproduces every evaluation table of the paper from scratch:
the solvers, the benchmark sets, the scripts that run each solver configuration
on each set, and the script that summarizes the results.

| Paper table        | Selection | What it compares | Configurations | Runs |
|--------------------|-----------|------------------|---------------:|-----:|
| `eval_pbv.tex`     | `pbv`     | PBV benchmarks: Pbv, Pbv+ vs. cvc5 and its T_PBV ablations (`rr`, `lr`, `piand`) | 8 | 124,002 |
| `eval_cav26.tex`   | `cav26`   | CAV'26 sets: ParaBit, Pbv+, cvc5-pbv, in enumeration and single-formula (ite) encodings | 5 | 8,831 |
| `eval_exp.tex`     | `exp`     | EIA benchmarks: SwInE (Z3, cvc5, reimplementation) vs. the cvc5 exponentiation ablations | 10 | 114,890 |
| `eval_oopsla.tex`  | `oopsla`  | Unbounded solvers of OOPSLA'26 (rIC3, k-induction) vs. Pbv, Pbv+, cvc5-pbv | 5 | 2,640 |

Every run has a 60 s CPU-time limit and an 8 GB memory limit, as in the paper.

## Web playground

`index.html` (served by GitHub Pages) runs the solvers in the browser, compiled to
WebAssembly: cvc5 with T_PBV (every cvc5 configuration of the paper is a preset) and
ParaBit. Enter SMT-LIB (or bwlang for ParaBit), pick a configuration or edit the
arguments, and press Run; *Share* puts the input and the configuration in the URL.
The binaries are in `wasm/`; `web/build-wasm.sh` rebuilds them from source (patches in
`web/patches/`). Pbv/Pbv+, SwInE and the OOPSLA'26 solvers are native only.
Locally: `python3 -m http.server` in this directory, then open http://localhost:8000.

Not in the Git repository (over GitHub's 100 MB file limit): `solvers/unb-kind`,
`solvers/unb-ric3`, `benchmarks/paper-benchmarks.tar.gz` and
`benchmarks/sets/pbv_QF_PBV_two_bitwidth.tar.gz`.

## Requirements

* Linux x86-64 (the solvers are prebuilt binaries)
* bash, python3 (3.8+), tar, gzip
* for the analysis: the Python package `polars` (`pip install polars`)
* recommended: [BenchExec](https://github.com/sosy-lab/benchexec) (`pip install benchexec`,
  needs cgroups; see its documentation). Its `runexec` measures time and memory
  exactly as in the paper. Without it, `run_local.py` uses a fallback (see below).

## 1. Setup

```bash
cd paper-artifact
bash scripts/setup.sh
```

This unpacks every `benchmarks/sets/*.tar.gz` into `data/`, writes the set lists
with local paths to `data/benchmark_set_*`, and creates `bin/` (links to
`solvers/`; the wrappers' paths are rewritten into `bin/`). It is idempotent:
run it again after moving the directory. `bash scripts/setup.sh SET...` unpacks
only the given sets.

## 2. Run

```bash
bash scripts/run_experiments_paper-tables.sh --list          # tables and their configurations
bash scripts/run_experiments_paper-tables.sh all             # the whole evaluation
bash scripts/run_experiments_paper-tables.sh pbv exp         # whole tables
bash scripts/run_experiments_paper-tables.sh pbv:cvc5-pbv,cvc5+rr cav26:cvc5-pbv-ite   # single configurations
bash scripts/run_experiments_paper-tables.sh --dry-run all   # only print the commands
```

Options:

| Option | Meaning |
|---|---|
| `--backend local` | (default) run on this machine with `scripts/run_local.py` |
| `--backend slurm` | submit one Slurm array job per (configuration, set) with `scripts/submit-job.sh` |
| `--jobs N` | local backend: runs in parallel (default: min(#CPUs, RAM / 8 GB)) |
| `--time-limit=SEC` | CPU-time limit per benchmark (default 60) |
| `--smoke-test` | instead of a selection: a partial Table 11 in ~5 minutes (see below) |
| `WD_BASE=DIR` (env) | results directory (default `results/`) |

Results go to `results/<table>/<config>/<set>/<benchmark>/{run.out,output.log}`,
and `results/<table>/<config>/options` records the exact command.

**Smoke test.** `bash scripts/run_experiments_paper-tables.sh --smoke-test` checks the
artifact in a few minutes (115 s with 7 parallel runs on a 14-core laptop, without setup.sh
and without runexec). It runs the 7 solver columns of Table 11 (`eval_pbv.tex`) on 48
benchmarks, 2–5 from each PBV set (`benchmark_sets/benchmark_set_smoke_*`; their files are in
`benchmarks/sets/smoke_*.tar.gz` and are unpacked automatically). The sample has, per set,
benchmarks every configuration solves and benchmarks that separate the configurations; each
one was either solved in < 0.5 s or timed out in the paper's runs, so the smoke test uses a
5 s limit (`--time-limit` overrides) and 2 GB per run, which allows more parallel runs.
At the end, `scripts/smoke_report.py` prints the solved counts per set and configuration
next to the paper's (`benchmarks/smoke-expected.tsv`), and lists every benchmark with a
different verdict; it exits with 1 on a wrong answer (sat vs. unsat).
Results: `results/smoke/`.

**Run time.** The full evaluation is ~238,000 solver runs. Most finish in well
under a second, but every timeout costs 60 s, so a full run on one machine
takes days to weeks. The paper used a Slurm cluster of 22 machines with Intel
Xeon Gold 6348 CPUs. On a single machine, run single tables or configurations,
or a subset of the sets (`setup.sh SET...`).
The local runner **resumes**: rerunning the same selection skips every benchmark
that already has a `run.out`, so an interrupted run can simply be restarted.

**Local measurements.** With `runexec` installed, `run_local.py` uses it with the
same options as the cluster. Otherwise it limits CPU time with `RLIMIT_CPU` and
memory with `RLIMIT_AS`, measures CPU time and peak RSS of the solver process tree
(`wait4`), and classifies a run as a timeout when it used the full CPU time, and as
a memory-out when it failed while out of memory. `results/<table>/<config>/options`
says which was used. Solved counts can differ slightly from the paper near the
time limit on a different CPU.

**Memory.** Every run may use up to 8 GB, and some solvers do (ParaBit, the
unbounded solvers). Keep `--jobs` × 8 GB below the machine's RAM: the default does
this, and `run_local.py` warns when `--jobs` exceeds it. Otherwise runs are killed
by the kernel's OOM killer or slowed down by swapping, which changes the results.

**Slurm.** `scripts/submit-job.sh` is the submitter of the cluster used for the
paper. Before using it elsewhere, adapt its partition/account (`p_zohar`,
`ug_zohar`), the `benchexec` group check, and the `runexec` location. The Slurm
backend never overwrites: it skips a configuration whose results directory exists.

## 3. Analyze

`cmpr.py` prints one row per (configuration, set) with the number of benchmarks,
solved (sat/unsat), timeouts, memory-outs, errors, disagreements and total CPU time;
`-t` adds a total row per configuration.

```bash
cd results
# eval_pbv.tex
python3 ../scripts/cmpr.py pbv/*/pbv_* -t
# eval_exp.tex
python3 ../scripts/cmpr.py exp/*/exp_* -t                   # sets: exp_LoAT exp_PURRS exp_q_sat25 exp_qf_sat25
# eval_cav26.tex: enumeration encoding (one problem = all its generated widths) ...
python3 ../scripts/cmpr-cav26.py cav26/*-enum/cav26_* -t --collapse
# ... and ParaBit + single-formula encoding
python3 ../scripts/cmpr.py cav26/parabit/cav26_* cav26/*-ite/cav26_* -t
# eval_oopsla.tex
python3 ../scripts/cmpr.py oopsla/*/*_* -t
```

`python3 ../scripts/cmpr.py -h` lists further options (grouping, filtering, other columns).

## Configurations

All cvc5 configurations use `--nl-ext-tplanes --full-saturate-quant` plus:

| Config (paper) | Directory | Additional cvc5 options |
|---|---|---|
| cvc5 | `cvc5` | – |
| cvc5^+fermat | `cvc5+fermat` | `--fermat-little-theorem` |
| cvc5^+mod | `cvc5+mod-reducer` | `--learned-rewrite-rules=int` |
| cvc5^+pre | `cvc5+pre` | `--exp-preprocess=multiply` |
| cvc5^+exp-no-phasing | `cvc5+exp-no-phasing` | `--exp-solver=rewrites,lemmas` |
| cvc5^+exp | `cvc5+exp` | `--exp-solver=rewrites,lemmas,phasing` |
| cvc5-exp | `cvc5-exp` | `--exp-solver=rewrites,lemmas,phasing --exp-preprocess=multiply --fermat-little-theorem --learned-rewrite-rules=int` |
| cvc5^+rr | `cvc5+rr` | `--pbv-rewrites` |
| cvc5^+lr | `cvc5+lr` | `--learned-rewrite-rules=pbv` |
| cvc5^+piand | `cvc5+piand` | `--piand-lemmas=complement,mask,mask-sym,subset-trans,pow2-idiom` |
| cvc5-pbv | `cvc5-pbv`, `cvc5-pbv-enum`, `cvc5-pbv-ite` | cvc5-exp options with `--learned-rewrite-rules=int,pbv`, plus `--piand-lemmas=complement,mask,mask-sym,subset-trans,pow2-idiom --pbv-rewrites` |

Pbv and Pbv+ run with `--cvc5:"nl-ext-tplanes full-saturate-quant"`;
SwInE with `--solver z3` / `--solver cvc5`; ParaBit, the reimplementation of SwInE and
the unbounded solvers without options.
